# Manual QA — M01

Spec §12: *"Manual QA script (run before every release; 12 minutes)."*

The automated suite covers a great deal and cannot cover this: whether the
screens are **usable**, whether the copy reads as a diagnosis rather than a
verdict, and whether a keyboard user can get anywhere. Each step below is one a
test cannot make for you.

```bash
Backend/.venv/Scripts/python -m pytest        # must be green before you start
start_resume.bat                              # API :8101 · web :5201
```

Tick as you go. A step that fails is a release blocker unless somebody writes
down why it is not.

---

### 1 · Two-column resume → reading order  (2 min)

Upload a real two-column PDF (a Canva or Overleaf export; not one generated by
the test suite).

- [ ] The confirmation screen says it looks like a two-column layout
- [ ] The left column's sections come out before the right column's
- [ ] The name is on the first line, not in the middle of the skills list
- [ ] A wrapped bullet is **one** claim, with its number attached

> The failure this catches is Trap 2 — interleaved columns. It looks like a
> model problem and is a layout problem, and it does not look wrong until you
> read the text.

### 2 · Scanned resume → the OCR path  (1 min)

Upload a photographed or scanned PDF with no text layer.

- [ ] Without an OCR engine: a **named** error that mentions pasting instead
- [ ] Never a silent empty parse, and never a stack trace
- [ ] With `pip install -e ".[ocr]"`: it parses, and the screen says the read
      came from an image

### 3 · Click a claim → the document highlights  (1 min)

- [ ] Clicking any claim scrolls the document panel and highlights that bullet
- [ ] The highlight is the *right* bullet, not an approximate one
- [ ] The contact block shows as █ and the note explains why

> §8.3 calls this "a 4-hour feature that buys enormous trust". Verify the trust
> is earned: a highlight on the wrong line is worse than none.

### 4 · Edit a bullet → it re-scores  (1 min)

Take a bullet in **risky**. Add a measurement to it.

- [ ] It re-scores in under a second
- [ ] The band can visibly move
- [ ] No other claim's score changed
- [ ] The card says "you edited this"

### 5 · Delete every claim → the product still works  (1 min)

In the confirmation editor, use **not mine** on each bullet in turn.

- [ ] Claims can be deleted one at a time, and each asks before it goes
- [ ] With none left, the Claim Map is an empty state and not an error
- [ ] "Looks right — continue" still works
- [ ] Each removal appears on **How this was read** as a correction

> This step described a control that did not exist for a while. The endpoint
> was there, the QA script assumed a button, and the button was never built —
> which is exactly the gap `pytest -m gate` now catches from the other side.

### 5b · Fix a date the parser invented  (1 min)

Find a date range under **Dates** that is not a date — a graph size, a version
number, anything the reader grabbed.

- [ ] **not a date** removes it, and the timeline flag that depended on it goes
- [ ] Typing a real range ("Jun 2025 - Aug 2025") saves and re-reads it
- [ ] Typing nonsense says *I could not read that as a date range* and changes
      nothing — not a silent failure, and not a stored string
- [ ] Reclassifying a bullet ("I built it" over "I used it") changes the
      questions it invites

### 6 · Skip → a real destination  (1 min)

From the upload screen, press **Skip for now**.

- [ ] Skip is a real button, not a grey link
- [ ] It lands somewhere with content, not a dead end
- [ ] Nothing on that page is broken by the absence of a resume

> FR-1.14 is a P0 and it is the requirement most easily broken by accident,
> because every later feature assumes a resume exists.

### 7 · Re-upload → the diff  (1 min)

Upload a revised copy of a resume already stored for this candidate.

- [ ] "What changed since last time" shows added / removed / re-banded
- [ ] A bullet rewritten to add a number appears under **Rewritten** and says
      the rewrite helped
- [ ] Uploading the identical file says so rather than showing an empty diff

### 7b · Who can see this  (1 min)

From the claim map, open **Who can see this**.

- [ ] **Show contact details** is a button, not a field that was already filled
      in — and the panel says the request is recorded
- [ ] Granting `placement-cell` and then asking what `placement-cell` sees
      moves the answer from *counts only* to *your individual claims*
- [ ] Withdrawing moves it back, and says so
- [ ] The retention date is a real date, and the pending sign-off is visible
      rather than implied
- [ ] Deleting says what survives deletion **before** the button, not after

### 7c · Parser quality  (1 min)

- [ ] `/quality` renders without a resume selected
- [ ] The edit rate is drawn against §13's line and the verdict is a word, not
      only a colour
- [ ] Unset PII key and absent virus scan read as known gaps, not as errors

> Both of these were endpoints with no screen. If either page is blank, check
> `pytest -m gate` — the contract test fails on a route with no client, so a
> blank page here means the wiring was removed rather than never added.

### 8 · Keyboard only  (2 min)

Put the mouse down. Tab from the top of the page.

- [ ] The skip link appears on the first Tab and works
- [ ] **Every** focused element has a visible ring
- [ ] `j` / `k` move between claims and the selection is visibly obvious
- [ ] `e` opens the editor, `Enter` opens the rewrite
- [ ] Nothing traps focus

### 9 · Screen reader, Screens 1–4  (2 min)

- [ ] Parse stages are announced as they land
- [ ] Each claim is announced with its band as a WORD ("Risky claim: …"),
      never by colour
- [ ] The document panel is reachable and readable
- [ ] Every control has a name that says what it does

---

## The copy check

Read the Claim Map as a nervous final-year student, not as its author.

- [ ] No number that could be mistaken for a score out of a hundred
- [ ] No sentence that judges the **person** rather than the claim
- [ ] Every risky claim says what an interviewer would ask, not just that it is risky
- [ ] Every red flag comes with a way to answer it
- [ ] The word "AI" appears nowhere on the upload screen

> §2.3's table is the standard: *"Weak bullet detected"* is wrong, *"An
> interviewer will ask: 94% on what split?"* is right. The first is a label; the
> second is a consequence you can act on.
